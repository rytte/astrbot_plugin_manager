# 插件管家 🧩

> 查插件、逛市场、找工具，安装与开关也顺手——聊天里的插件琐事，交给管家。

一个 `/pm` 入口，搞定 AstrBot 插件的日常管理；原生插件页面提供来源管理、插件清单分享和插件包备份迁移。**聊天命令仅限 AstrBot 管理员，页面仅限已登录的 WebUI 管理员**，无需额外第三方依赖。

## 🚀 快速上手

- **版本**：AstrBot `>=4.27.4,<5`，依赖原生插件页面及扩展 API，已在 `4.27.4` 验证；其他版本请先测试。
- **安装**：放入实际运行目录的 `data/plugins/astrbot_plugin_manager`。
- **开用**：重载插件或重启 AstrBot，发送 `/pm` 查看帮助。示例使用 `/` 前缀，以实际配置为准。

## 📋 命令速查

| 命令 | 管家能做什么 |
| --- | --- |
| `/pm help` | 查看帮助 |
| `/pm list` | 查看插件列表 |
| `/pm info <插件名>` | 查看插件信息 |
| `/pm source <插件名>` | 查看安装记录、当前更新源和关联数量 |
| `/pm reload <插件名>` | 重载插件 |
| `/pm enable <插件名>` | 启用插件 |
| `/pm disable <插件名>` | 停用插件 |
| `/pm search <关键词> [--page <页码>]` | 搜索官方插件市场 |
| `/pm add <仓库地址或市场ID>` | 从仓库或市场安装插件 |
| `/pm remove <插件名> [--all]` | 卸载插件 |
| `/pm cmds [页码]` | 查看全部命令 |
| `/pm tools [页码]` | 查看模型工具 |

插件名也可以填写**目录名**，默认允许省略 `astrbot_plugin_` 前缀，剩余名称仍须精确匹配。不做模糊匹配、批量操作或旧命令别名。除卸载外，管理员群聊、私聊都能用。

## 🛍️ 逛市场，看到就装

```text
/pm search 天气
/pm search 天气 --page 2
/pm add alice/astrbot_plugin_weather
/pm add https://github.com/alice/astrbot_plugin_weather
```

搜索按名称、作者、简介、标签和市场 ID 查找，每页 20 项，并附可复制的安装命令。示例 ID 仅作演示，请以搜索结果为准。当前只查询官方市场，不使用 WebUI 中选择的自定义市场；读取缓存时会明确提示。

- **作者/插件技术名**：按完整市场 ID 精确安装，不省略 `astrbot_plugin_` 前缀，也不把它当作 GitHub 仓库简写；找不到就报错，不自动换成仓库安装。ID 含空格时，用引号包住完整 ID。
- **完整仓库地址**：从代码仓库安装，支持 AstrBot 接受的 HTTP(S)、SSH 和 SCP 风格 Git 地址。
- 两种方式都保留 AstrBot 版本检查。市场安装交给官方服务解析下载包并保存来源；后续 WebUI 更新仍遵循原市场源，安装后也会核对作者与插件技术名。

## 🔎 指令与工具，一眼看清

`list` 一次列出全部插件；`cmds`、`tools` 每页 20 项，默认第一页，结果会附下一页命令：

```text
/pm cmds 2
/pm tools
/pm info dev_helper
```

插件列表有显示名称时显示 `显示名称（插件名）`；详情分别列出显示名称和插件名。未设置 `display_name` 时，列表只显示插件名，详情标注「显示名称：未声明」。加载失败插件按已有元数据展示显示名称，仍以目录名作为操作标识。显示名称只用于展示，不参与命令匹配。

工具目录包含插件工具、AstrBot 内置工具、已注册 MCP 工具，以及 Agent 入口和嵌套工具。同一工具对象只显示一次，不同对象即使同名也分别展示。`info` 只展示目标插件真正拥有的条目，不把它借用的其他插件或 MCP 工具算进去；参数只列名称，完整结构看 `tools`。

## ⚙️ 少打一点插件名

在 WebUI 的插件配置中切换 **允许省略插件名前缀**（`allow_prefix_omission`，默认开启）：

- 开启：`/pm reload example` 可操作 `astrbot_plugin_example`。
- 关闭：只接受原始插件全名或完整目录名。

对 `info`、`source`、`enable`、`disable`、`reload`、`remove` 的名称参数统一生效。短名若匹配不同插件，直接报歧义，不自动挑选目标；卸载仍需私聊确认。

改完插件代码？来一句：

```text
/pm reload astrbot_plugin_example
```

只重载这个插件，不全量重载、不重启 AstrBot。停用插件请先 `enable`，加载失败的请到 WebUI 恢复；共享依赖变更建议重启 AstrBot。

## 🗑️ 卸载，先确认再动手

在**管理员私聊**中申请，并在 **60 秒内**追加 `confirm` 确认。默认删除插件文件，保留配置与数据：

```text
/pm remove astrbot_plugin_example
/pm remove astrbot_plugin_example confirm
```

想连配置、文件数据和 KV 数据一起清理？**两次都带上 `--all`**：

```text
/pm remove astrbot_plugin_example --all
/pm remove astrbot_plugin_example --all confirm
```

确认必须来自同一管理员、同一平台私聊，目标和删除范围也要一致。超时、管家重载或 AstrBot 重启后，需要重新申请。

## 💡 使用边界

- 管家不能停用或卸载自己，AstrBot 保留插件也不能卸载。
- 聊天命令操作失败可能已产生部分变更，不会自动回滚；请到 WebUI 核对或恢复，避免反复重试。页面导入的恢复机制见下节。

## 📦 插件备份与迁移页面

在 WebUI 打开**插件管家 → 插件页面**，进入统一的「插件管家」页面。顶部提供「导出 / 分享」「导入 / 恢复」「任务记录」三个功能区，导出摘要仅在导出页显示：ZIP 用于备份插件代码、配置与标准数据，JSON 清单用于分享插件列表并从官方市场重新安装。插件列表直接显示当前更新来源；点击「来源管理」可查看安装记录、当前更新源并管理来源绑定。更新后请重载插件并刷新 WebUI。

列表合并运行中、加载失败和磁盘上待扫描的插件，支持按显示名称、插件名、目录搜索和按运行状态筛选。插件名称左侧显示安装目录中的 `logo.png`，使用 AstrBot 原生临时文件接口；缺失或加载失败时显示默认插件图标。ZIP 与 JSON 使用独立的插件选择，切换格式保留尚未保存的 ZIP 选择和两种导入预检；刷新页面后需重新上传预检。

### 安装记录与来源关联

这三类信息分别保存，不将它们混为一谈：

| 信息 | 含义 |
| --- | --- |
| 安装记录 | 管家亲自执行安装时记录方式与时间；旧插件只记录首次观察到的 AstrBot 来源，无法还原最初安装历史 |
| 已关联来源 | 一个插件可以同时关联官方市场 ID 和仓库 URL，保留最近 100 条来源操作记录 |
| 当前更新源 | 唯一生效的来源，读取并同步 AstrBot 原生 `plugin_install_sources`，供原生 WebUI 更新使用 |

没有记录或带 `implicit: true` 的插件显示「来源未知」，不会推断成市场安装。新增关联也不会改变最初安装记录。来源扩展信息保存在 `data/plugin_data/astrbot_plugin_manager/sources.json`；原生绑定在其他入口发生变化时，会保留旧关联并记录观察结果。

1. 点击插件旁的「来源管理」，填写完整的官方市场 ID（`作者/插件技术名`）或不含凭据的 HTTPS Git 仓库地址。
2. 点击「校验身份」：远端插件名、作者须与本机一致；已有当前来源的仓库地址不一致时拒绝关联。
3. 点击「保存关联」后，自动设为当前更新源并同步到 AstrBot。也可在已有来源旁点击「设为更新源」，切换前会重新校验。

校验预览有效期为 10 分钟，身份或来源变化后需要重新校验。元数据匹配不证明磁盘代码与仓库相同，也不证明代码安全。内置插件、身份不完整、磁盘与运行时插件名不同的插件禁止修改来源。目录被其他插件名复用时隔离旧记录；管家确认卸载后会归档记录，重新安装建立新的安装记录。自定义市场记录可展示，第一版不支持新增或切换自定义市场关联。

修改作者、显示名称、版本等元数据后，页面保留插件真实启停状态，显示「插件信息已变更」及「更新信息」按钮。点击只同步管家记录和匹配的导出规则，不重载插件、不修改源码、不迁移数据，也不改写 AstrBot 的当前更新源或最初安装记录。作者改变后保留来源关联，但须重新校验才能用于分享清单。插件技术名变化仍按身份冲突检查。

键值数据按运行中插件实际使用的标识读取，修改作者不会让统计误读新标识下的数据。代码和配置可以直接备份；若作者变化且插件仍在运行，附带标准数据前须先停用该插件，避免导出后的自动重载切换数据标识。停用后备份会读取原标识的键值数据，恢复该备份时写入包内新作者对应的标识。

管家与自身任务共用操作锁，关键写入持有 AstrBot 核心插件锁并重新检查来源；原生其他入口未提供跨文件和数据库的原子事务，操作时请避免同时在其他页面修改同一插件来源。

### JSON 清单：分享与从市场安装

1. 在「导出 / 分享」将「导出内容」选为「插件清单 JSON · 分享安装」。给要分享的插件关联官方市场 ID，勾选后点击「导出清单 JSON」。当前更新源可以仍是仓库；未关联官方市场的插件不能勾选。
2. 将 `plugins.astrbot-plugin-manifest.json` 分享给对方；它只包含市场身份、参考版本与版本策略，不包含代码、配置、数据或下载 URL。
3. 接收者在「导入 / 恢复」将「导入内容」选为「插件清单 JSON · 从市场安装」，上传 JSON，查看当前官方市场版本、本机已有项和冲突；仅通过预检的新插件默认勾选。
4. 核对后启动安装，在任务记录查看逐项结果。已有同身份插件跳过，不修改其版本、来源或启停状态；冲突插件禁止覆盖。

清单格式为 `astrbot-plugin-manager-manifest` v1，最多 256 项、8 MiB，拒绝未知字段、任意下载地址、重复身份、自定义市场和固定版本策略。例如：

```json
{
  "format": "astrbot-plugin-manager-manifest",
  "schema_version": 1,
  "created_at": "2026-10-11T00:00:00Z",
  "plugins": [{
    "market_plugin_id": "alice/astrbot_plugin_example",
    "name": "astrbot_plugin_example",
    "author": "alice",
    "observed_version": "1.0.0",
    "registry": "official",
    "version_policy": "latest"
  }]
}
```

`observed_version` 仅作参考，实际安装以预检时官方市场的当前版本为准。安装执行前重新获取市场条目，版本、仓库、下载地址或本机目标发生变化则拒绝该项并要求重新预检；仅有市场缓存时停止安装。安装包来自本机解析的官方市场，不读取清单提供的下载位置。

每个包先在任务暂存区检查路径、大小、包内名称/作者/版本、AstrBot 版本和已安装依赖；第一版只接受根目录或唯一外壳目录下包含 `metadata.yaml` 与 `main.py` 的包。**安装过程不执行插件代码、不运行 pip，写入后保持停用。请重启 AstrBot 扫描后手动启用。** 缺失依赖会使该项失败。市场包与迁移包使用相同大小上限，逐项预留约 1.25 GiB 加安全余量。

单项失败会记录并继续其他项，已成功项不回滚。目录写入后的来源写入失败会尝试撤回该项并恢复来源及停用偏好；自动恢复失败则停止后续项。进程中断不自动续跑，检查私有 `job.json` 中的 `pending_install` 恢复记录。任务持久化、用户隔离及手动删除规则与备份迁移一致。下载包 SHA-256 保留在任务记录用于追溯；第一版没有签名或可信包哈希认证，清单不能保证代码安全。

当前已提供来源与清单基础能力。聊天更新命令、固定版本/提交、签名验证与自定义市场清单属于后续阶段。

### ZIP 插件包：备份与恢复

#### 导出：选择内容，按需应用规则

1. 在「导出 / 分享」将「导出内容」选为「插件包 ZIP · 备份环境」，选择插件。列表同时显示 `display_name`、插件名及目录名，支持搜索、状态筛选；表头全选框只影响当前筛选中的可选插件，保留筛选外的选择。批量操作区显示总选中数，可清空选择或批量附带数据、配置；部分插件附带时显示半选状态。
2. 每个插件必带代码，可独立勾选**标准数据**、**当前配置**，也可批量调整所选插件的附带内容。
3. 页面打开时默认不勾选插件。可点击「保存规则」保存当前实例共享的一套常用选择，需要时点击「应用已保存规则」恢复插件、数据和配置选项，再继续调整。刷新状态保留本次选择；保存空选择会清空规则。规则中插件缺失、身份变化或组件不可用时会明确提示并拒绝应用，保留本次选择。
4. 点击「导出插件包」，按**当前选择**预检并确认暂停和敏感内容风险，无须先保存规则，也不会覆盖已保存的规则。确认后的任务使用本次预检的选择，其他人修改保存规则不会改变本次导出范围；规则不固定插件版本，导出读取执行时的实际文件。
5. 在「任务记录」等待完成并下载 ZIP。含标准数据的已启用插件会在快照时暂停，随后尝试恢复原启用状态；恢复失败会显示警告，请在 WebUI 检查。

**组件范围**：

| 组件 | 导出内容 |
| --- | --- |
| 代码（必选） | `data/plugins/<目录名>/`；排除 `.git`、`.venv`、`venv`、`node_modules`、`__pycache__` 及 Python 字节码 |
| 来源信息（默认附带） | 安装来源、关联的市场 ID / 仓库地址，以及备份时的当前更新源；不包含操作历史、地址中的凭据或校验认证 |
| 当前配置（可选） | `data/config/<目录名>_config.json` 中已落盘的配置，不会补默认值 |
| 标准数据（可选） | `data/plugin_data/<插件名>/` 和插件专属 KV（按真实 `plugin_id` 定位）；SQLite 使用 Backup API 快照 |

这里的路径以 AstrBot 标准布局为例，代码、配置路径实际取自运行中的插件管理器。插件名、目录名和 `plugin_id` 不必相同。未勾选数据仍可能带出**插件自行放在代码目录内的运行数据**。不包含 AstrBot 全局配置、其他插件的 KV、共享目录或外置数据库，也不会自动迁移绝对路径和外部资源。

#### 导入：上传预检，再选择覆盖组件

1. 在「导入 / 恢复」将「导入内容」选为「插件包 ZIP · 恢复备份」，选择本功能生成的 ZIP；普通插件安装 ZIP 和恢复资料 ZIP 都不接受。
2. 上传只解压到隔离暂存区，检查路径、身份、校验值、版本、依赖和组件声明，**不执行插件代码**。预检一小时内有效；目标文件或启停状态变化后须重新上传。
3. 按插件勾选恢复代码、配置或标准数据。**现有插件默认全部跳过，新插件必须带代码**；未选组件不动，标准数据整体替换、不合并，包内空数据也会清空所选目标数据。
4. 确认后，先暂停相关插件、备份即将覆盖的本机组件和 KV，再逐插件恢复。配置按所选代码的 schema 严格校验，不做类型转换、补默认值、删除未知字段或旧字段兼容。
5. **导入完成后保持停用，不自动安装依赖或启用插件。请重启 AstrBot 扫描插件，再到 WebUI 手动启用。** 缺失或冲突的依赖需要人工处理；第一版拒绝 URL、extras、pip 参数及外部依赖文件。

保留插件不参与迁移。管家自身可导出代码、配置，但禁止附带自身数据；第一版禁止在线导入覆盖管家自身。目标身份冲突会拒绝，不会自动改名或替换其他插件。

ZIP v2 默认在每个插件的 `payload/<目录名>/sources.json` 中保存来源信息。覆盖代码时一并恢复来源，安装来源标注为备份中的参考记录，关联来源标记为「待校验」，并标明备份时的更新源；不会继承远端校验结果或自动写入 AstrBot 当前更新源。可在来源管理中点击「校验并设为更新源」，通过校验后恢复更新能力；待校验的市场关联不能直接用于分享清单。来源地址仅迁移不含凭据的 HTTPS 地址，不支持的地址会省略并在任务中提示。

继续兼容不含来源信息的 ZIP v1：覆盖代码后清除本机旧的更新源与关联，之后可重新绑定。两种格式仅恢复配置或数据时均保留本机来源。覆盖前的恢复资料会保存本机完整来源快照，自动回滚时一并恢复。新版 ZIP 需要使用支持 v2 的插件管家导入。

### 任务与失败恢复

- 同时只运行一个导入/导出任务，并与聊天管理操作共用锁；正式快照和恢复还持有 AstrBot 核心插件锁。
- ZIP 导出/导入、清单导出/安装共用「任务记录」，记录持久化，刷新页面不丢进度；下载及详细记录仅任务创建的 WebUI 用户可访问。ZIP 导出规则在当前实例内共享。
- 导入某插件失败时尝试恢复该插件的本机备份和原启用状态，后续插件不执行；**之前已成功导入的插件不会撤销**，因此不是整批事务。
- 覆盖前的「恢复资料」可下载，含 `rollback.json` 和 `before/<目录名>/`。它与迁移包格式不同，**不能通过导入按钮直接恢复**。
- 进程中断或自动恢复失败会明确标记，不会自动继续覆盖；这些恢复资料不会自动过期删除。请先停止 AstrBot，根据 `rollback.json` 的组件存在标记恢复文件：代码回到插件目录，配置回到配置文件，数据回到插件数据目录；原组件不存在则移除新增组件。`kv.json` 是带类型标记的专属 KV 快照，不要直接覆盖 AstrBot 全局数据库；KV 及启停偏好需按记录的 `plugin_id`、`module_path`、`was_enabled`、`was_inactive` 人工核对恢复，必要时借助维护脚本。
- 任务记录、导出包、清单和恢复资料持续保留，不按时间自动清理。可在「任务记录」中打开任务右上角的「⋯」菜单，选择「删除记录及文件」，确认后删除该任务目录中的全部文件及记录；已安装插件及本机配置、数据保持当前状态。上传、预检、排队或执行中的任务不可删除；包含恢复资料或异常中断的任务会额外提示确认。默认存储于 `data/plugin_data/astrbot_plugin_manager/transfers/`。
- 导入及清单安装预检仍仅在 1 小时内可确认执行，过期不会删除记录或文件，需重新上传预检。旧版已经自动清理的文件无法恢复，对应记录仍可手动删除。

新恢复资料的 `rollback.json` 还包含 `source_state`。手工恢复时需将其中 `record` 恢复到管家 `sources.json` 的对应目录项，并通过 AstrBot 偏好存储恢复 `core` 中指定的来源键；值为 `null` 表示原来不存在。只恢复这些键，避免覆盖其他插件的来源记录。

### 安全与限制

包格式仅支持 `astrbot-plugin-manager` v1，不接受未知版本或旧字段。校验值检查损坏，**不证明插件来源可信**；请只导入可信来源，启用代码前自行审核。

- 压缩包不超过 **256 MiB**，解压内容不超过 **1 GiB**，单文件不超过 **128 MiB**，JSON 不超过 **8 MiB**，最多 **256 个插件**、**20,000 个文件与目录节点**。
- 拒绝路径穿越、符号链接、目录联接、硬链接、特殊文件、Windows 保留名称和大小写/Unicode 冲突路径。无法完整读取目录时直接失败。
- 磁盘空间按任务内容估算：导出预留快照及打包空间，导入预留本机备份、恢复资料及替换空间，并额外留 **64 MiB** 安全余量；不够时在覆盖前失败。
- ZIP **不加密**。配置、插件文件和 KV 可能含 Token、Cookie、聊天记录等敏感内容，导出前明确确认；不要随意分享包或恢复资料。
- 页面 API 独立验证 WebUI JWT，拒绝 API Key 和仅用于加载页面资源的 token；写操作额外验证用户绑定的短期确认凭据。
