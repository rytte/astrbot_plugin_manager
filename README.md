# 插件管家 🧩

> 查插件、看指令、找工具，安装与开关也顺手——聊天里的插件琐事，交给管家。

一个 `/pm` 入口，搞定 AstrBot 插件的日常管理；原生插件页面负责插件包备份与迁移。**聊天命令仅限 AstrBot 管理员，页面仅限已登录的 WebUI 管理员**，无需额外第三方依赖。

## 🚀 快速上手

- **版本**：AstrBot `>=4.27.4,<5`，依赖原生插件页面及扩展 API，已在 `4.27.4` 验证；其他版本请先测试。
- **安装**：放入实际运行目录的 `data/plugins/astrbot_plugin_manager`。
- **开用**：重载插件或重启 AstrBot，发送 `/pm` 查看帮助。示例使用 `/` 前缀，以实际配置为准。

## 📋 命令速查

| 命令 | 管家能做什么 |
| --- | --- |
| `/pm help` | 查看帮助 |
| `/pm list` | 查看插件列表 |
| `/pm info <插件名>` | 查看插件信息 |
| `/pm reload <插件名>` | 重载插件 |
| `/pm enable <插件名>` | 启用插件 |
| `/pm disable <插件名>` | 停用插件 |
| `/pm add <仓库地址>` | 安装插件 |
| `/pm remove <插件名> [--all]` | 卸载插件 |
| `/pm cmds [页码]` | 查看全部命令 |
| `/pm tools [页码]` | 查看模型工具 |

插件名也可以填写**目录名**，默认允许省略 `astrbot_plugin_` 前缀，剩余名称仍须精确匹配。不做模糊匹配、批量操作或旧命令别名。除卸载外，管理员群聊、私聊都能用。

## 🔎 指令与工具，一眼看清

`list` 一次列出全部插件；`cmds`、`tools` 每页 20 项，默认第一页，结果会附下一页命令：

```text
/pm cmds 2
/pm tools
/pm info dev_helper
```

插件列表有显示名称时显示 `显示名称（插件名）`；详情分别列出显示名称和插件名。未设置 `display_name` 时，列表只显示插件名，详情标注「显示名称：未声明」。加载失败插件按已有元数据展示显示名称，仍以目录名作为操作标识。显示名称只用于展示，不参与命令匹配。

工具目录包含插件工具、AstrBot 内置工具、已注册 MCP 工具，以及 Agent 入口和嵌套工具。同一工具对象只显示一次，不同对象即使同名也分别展示。`info` 只展示目标插件真正拥有的条目，不把它借用的其他插件或 MCP 工具算进去；参数只列名称，完整结构看 `tools`。

## ⚙️ 少打一点插件名

在 WebUI 的插件配置中切换 **允许省略插件名前缀**（`allow_prefix_omission`，默认开启）：

- 开启：`/pm reload example` 可操作 `astrbot_plugin_example`。
- 关闭：只接受原始插件全名或完整目录名。

对 `info`、`enable`、`disable`、`reload`、`remove` 的名称参数统一生效。短名若匹配不同插件，直接报歧义，不自动挑选目标；卸载仍需私聊确认。

改完插件代码？来一句：

```text
/pm reload astrbot_plugin_example
```

只重载这个插件，不全量重载、不重启 AstrBot。停用插件请先 `enable`，加载失败的请到 WebUI 恢复；共享依赖变更建议重启 AstrBot。

## 🗑️ 卸载，先确认再动手

在**管理员私聊**中申请，并在 **60 秒内**追加 `confirm` 确认。默认删除插件文件，保留配置与数据：

```text
/pm remove astrbot_plugin_example
/pm remove astrbot_plugin_example confirm
```

想连配置、文件数据和 KV 数据一起清理？**两次都带上 `--all`**：

```text
/pm remove astrbot_plugin_example --all
/pm remove astrbot_plugin_example --all confirm
```

确认必须来自同一管理员、同一平台私聊，目标和删除范围也要一致。超时、管家重载或 AstrBot 重启后，需要重新申请。

## 💡 使用边界

- 管家不能停用或卸载自己，AstrBot 保留插件也不能卸载。
- 聊天命令操作失败可能已产生部分变更，不会自动回滚；请到 WebUI 核对或恢复，避免反复重试。页面导入的恢复机制见下节。

## 📦 插件备份与迁移页面

在 WebUI 的插件管理中打开**插件管家 → 插件页面 → 插件备份与迁移**。入口由 AstrBot 自动发现 `pages/transfer/index.html`，不是独立公开站点；若更新后未出现入口，请重启 AstrBot。

### 导出：保存规则，再按规则打包

1. 在「导出插件包」选择插件，列表同时显示 `display_name`、插件名及目录名，支持搜索、状态筛选和选择当前筛选结果。
2. 每个插件必带代码，可独立勾选**标准数据**、**当前配置**，也可批量调整所选插件的附带内容。
3. 点击「保存导出规则」，保存当前实例共享的一套选择；规则不固定插件版本，以后导出读取当时的文件。保存空选择会清空规则。
4. 点击「按规则导出」，检查清单并确认暂停和敏感内容风险。未保存的改动必须先保存，缺失或身份变化的插件会明确报错，不会静默跳过。
5. 在「任务记录」等待完成并下载 ZIP。含标准数据的已启用插件会在快照时暂停，随后尝试恢复原启用状态；恢复失败会显示警告，请在 WebUI 检查。

**组件范围**：

| 组件 | 导出内容 |
| --- | --- |
| 代码（必选） | `data/plugins/<目录名>/`；排除 `.git`、`.venv`、`venv`、`node_modules`、`__pycache__` 及 Python 字节码 |
| 当前配置（可选） | `data/config/<目录名>_config.json` 中已落盘的配置，不会补默认值 |
| 标准数据（可选） | `data/plugin_data/<插件名>/` 和插件专属 KV（按真实 `plugin_id` 定位）；SQLite 使用 Backup API 快照 |

这里的路径以 AstrBot 标准布局为例，代码、配置路径实际取自运行中的插件管理器。插件名、目录名和 `plugin_id` 不必相同。未勾选数据仍可能带出**插件自行放在代码目录内的运行数据**。不包含 AstrBot 全局配置、其他插件的 KV、共享目录或外置数据库，也不会自动迁移绝对路径和外部资源。

### 导入：上传预检，再选择覆盖组件

1. 在「导入插件包」选择本功能生成的 ZIP；普通插件安装 ZIP 和恢复资料 ZIP 都不接受。
2. 上传只解压到隔离暂存区，检查路径、身份、校验值、版本、依赖和组件声明，**不执行插件代码**。预检一小时内有效；目标文件或启停状态变化后须重新上传。
3. 按插件勾选恢复代码、配置或标准数据。**现有插件默认全部跳过，新插件必须带代码**；未选组件不动，标准数据整体替换、不合并，包内空数据也会清空所选目标数据。
4. 确认后，先暂停相关插件、备份即将覆盖的本机组件和 KV，再逐插件恢复。配置按所选代码的 schema 严格校验，不做类型转换、补默认值、删除未知字段或旧字段兼容。
5. **导入完成后保持停用，不自动安装依赖或启用插件。请重启 AstrBot 扫描插件，再到 WebUI 手动启用。** 缺失或冲突的依赖需要人工处理；第一版拒绝 URL、extras、pip 参数及外部依赖文件。

保留插件不参与迁移。管家自身可导出代码、配置，但禁止附带自身数据；第一版禁止在线导入覆盖管家自身。目标身份冲突会拒绝，不会自动改名或替换其他插件。

### 任务与失败恢复

- 同时只运行一个导入/导出任务，并与聊天管理操作共用锁；正式快照和恢复还持有 AstrBot 核心插件锁。
- 任务记录持久化，刷新页面不丢进度；下载及详细记录仅任务创建的 WebUI 用户可访问。导出规则在当前实例内共享。
- 导入某插件失败时尝试恢复该插件的本机备份和原启用状态，后续插件不执行；**之前已成功导入的插件不会撤销**，因此不是整批事务。
- 覆盖前的「恢复资料」可下载，含 `rollback.json` 和 `before/<目录名>/`。它与迁移包格式不同，**不能通过导入按钮直接恢复**。
- 进程中断或自动恢复失败会明确标记，不会自动继续覆盖；这些恢复资料不会自动过期删除。请先停止 AstrBot，根据 `rollback.json` 的组件存在标记恢复文件：代码回到插件目录，配置回到配置文件，数据回到插件数据目录；原组件不存在则移除新增组件。`kv.json` 是带类型标记的专属 KV 快照，不要直接覆盖 AstrBot 全局数据库；KV 及启停偏好需按记录的 `plugin_id`、`module_path`、`was_enabled`、`was_inactive` 人工核对恢复，必要时借助维护脚本。
- 普通任务的包、暂存区和恢复资料保留 7 天，初始化和创建任务时清理，过期下载会立即拒绝；记录仍保留。默认存储于 `data/plugin_data/astrbot_plugin_manager/transfers/`，清理前请确认不再需要恢复。

### 安全与限制

包格式仅支持 `astrbot-plugin-manager` v1，不接受未知版本或旧字段。校验值检查损坏，**不证明插件来源可信**；请只导入可信来源，启用代码前自行审核。

- 压缩包不超过 **256 MiB**，解压内容不超过 **1 GiB**，单文件不超过 **128 MiB**，JSON 不超过 **8 MiB**，最多 **256 个插件**、**20,000 个文件与目录节点**。
- 拒绝路径穿越、符号链接、目录联接、硬链接、特殊文件、Windows 保留名称和大小写/Unicode 冲突路径。无法完整读取目录时直接失败。
- 磁盘空间按任务内容估算：导出预留快照及打包空间，导入预留本机备份、恢复资料及替换空间，并额外留 **64 MiB** 安全余量；不够时在覆盖前失败。
- ZIP **不加密**。配置、插件文件和 KV 可能含 Token、Cookie、聊天记录等敏感内容，导出前明确确认；不要随意分享包或恢复资料。
- 页面 API 独立验证 WebUI JWT，拒绝 API Key 和仅用于加载页面资源的 token；写操作额外验证用户绑定的短期确认凭据。

## 开发验证

在包含相邻 `AstrBot` 源码目录的工作区运行；源码在其他位置时设置 `ASTRBOT_SOURCE`：

```powershell
.\AstrBot\.venv\Scripts\python.exe -m pytest astrbot_plugin_manager\tests -q
.\AstrBot\.venv\Scripts\python.exe -m ruff check astrbot_plugin_manager
```
