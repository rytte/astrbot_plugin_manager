# 插件管家 🧩

> AstrBot 插件的日常琐事，交给管家。

提供全面的插件管理命令，支持插件包的选择性迁移，插件清单导入导出，自动插件源绑定，提供 WebUI 页面。

## 🌟 功能亮点

- **管理命令**：用 `/pm` 查找安装、启停重载、检查更新和卸载插件；`info` 可查看指定插件的详情、命令和工具摘要。
- **插件页面**：提供 WebUI 插件页面，更加简单直观地管理插件，支持任务记录与回溯。
- **来源补充**：跟随 AstrBot 当前更新源，为缺失来源补关联，便于插件开发与更新管理。
- **清单分享**：导出 JSON 清单分享所选插件，接收者可按需选择插件和安装来源。
- **备份迁移**：选择要备份或恢复的插件，导出时按需附带配置和标准数据，导入时选择恢复范围。

## 📋 命令速查

| 命令 | 管家能做什么 |
| --- | --- |
| `/pm help` | 查看帮助 |
| `/pm list` | 查看插件列表 |
| `/pm add <仓库地址或市场ID>` | 安装插件 |
| `/pm remove <插件名> [--all]` | 卸载插件 |
| `/pm info <插件名>` | 查看插件信息 |
| `/pm enable <插件名>` | 启用插件 |
| `/pm disable <插件名>` | 停用插件 |
| `/pm reload <插件名>` | 重载插件 |
| `/pm update <插件名>` | 更新插件 |
| `/pm check-update` | 检查更新 |
| `/pm refresh-market` | 刷新插件市场 |
| `/pm search <关键词> [--page <页码>]` | 搜索插件市场 |

插件名允许省略 `astrbot_plugin_` 前缀。

## 💬 聊天里的日常管理

聊天命令仅限 AstrBot 管理员，插件页面仅限 WebUI 管理员。需要 AstrBot `>=4.27,<5`；示例使用 `/` 前缀，以你的实际配置为准。

### 找插件、装插件

搜索面向官方插件市场，安装可用市场 ID 或仓库地址：

```text
/pm search 天气
/pm add rytte/astrbot_plugin_manager
/pm add https://github.com/rytte/astrbot_plugin_manager
```

市场 ID 要写完整的 `作者/插件名`，这里不能省略 `astrbot_plugin_` 前缀；含空格时用引号包住。市场信息不够新时，用 `/pm refresh-market` 刷新。

管理已安装插件时，可以使用技术名或目录名，中文显示名只用于展示。`info` 一次查看插件信息、来源、命令和工具；停用后用 `enable` 开启，`reload` 只重载指定插件。加载失败的插件请到官方 WebUI 处理。

### 更新与卸载

`check-update` 按 AstrBot 当前来源检查市场或仓库中的版本；`update` 也可以直接使用，有新版本才更新，并保留原来的启停状态。没有更新源时，可在官方插件页面选择，或到管家「来源详情」中补充。

卸载需要再确认一次，由同一管理员在**同一会话、60 秒内**追加 `confirm`：

```text
/pm remove astrbot_plugin_example
/pm remove astrbot_plugin_example confirm
```

默认保留配置和数据。要一并删除，两次命令都加上 `--all`，其他参数也须一致。管家不能停用或卸载自己，AstrBot 内置插件不能卸载。

## 🖥️ 在 WebUI 里打理插件

打开 **插件管家 → 插件页面**。这里可以查看来源、分享插件和备份环境，进度与下载集中在「任务记录」。

- **来源详情**：显示 AstrBot 当前更新源、市场 ID 和仓库地址；常规换源请使用官方插件页面。管家启动和插件加载后，会在后台为未绑定的插件补充更新源：按作者和插件技术名匹配官方市场，本地有 `repo` 时额外校验仓库地址；唯一匹配时绑定市场源，市场未匹配且有 `repo` 时校验并绑定仓库源。`repo` 是可选字段，已有绑定保持不变；多项匹配、仓库冲突或联网校验失败会保留未绑定状态，并在来源详情显示原因。也可手动填写完整市场 ID 或不含凭据的 HTTPS 仓库地址，校验后保存到 AstrBot，同时补齐插件缺失的仓库元数据。ZIP 恢复会自动校验并绑定来源，未能确认的来源可在这里重试。
- **检查更新**：点击「检查更新」后，列表显示当前更新源的结果。有新版本时点击「更新」并确认，结果可在任务记录中查看。在官方页面换源后，重新检查即可；仓库源会直接读取远端元数据比较版本。
- **加载插件**：点击「待加载」标签，在弹窗中直接确认即可加载并启用，无须重启。期间显示「加载中…」，结果直接在页面提示，不生成任务记录。

插件信息变化时，点击「更新信息」同步管家记录；这一步不会重载插件。

## 📦 分享清单，备份环境

先按用途选格式：

| 格式 | 适合做什么 | 带走哪些内容 |
| --- | --- | --- |
| JSON 清单 | 把一组插件分享给别人 | 插件名称与安装来源，由接收者重新安装 |
| ZIP 插件包 | 备份或迁移现有环境 | 当前插件代码，可附带配置和标准数据 |

### 用 JSON 分享插件

1. 在「导出 / 分享」选择插件清单 JSON，勾选已有当前来源的插件后导出；官方市场来源自动提供市场 ID 和仓库地址，无须分别关联。
2. 对方在「导入 / 恢复」选择插件清单 JSON，上传并等待预检。
3. 选择要安装的插件和来源，确认后安装，在任务记录中查看结果。

清单不含配置和数据，也不锁定版本；实际版本以安装时的来源为准。已有同身份插件会跳过。选择会自动保存，可从任务记录「继续选择安装」；过期后重新预检即可。

### 用 ZIP 备份与迁移

**导出**：在「导出 / 分享」选择插件包 ZIP，勾选插件，按需附带配置和标准数据，再确认导出。完成后到任务记录下载。表头可全选当前筛选结果，常用组合可保存为导出规则；填写「导出名称」还可以自定义文件名。

附带标准数据时，已启用的普通插件会短暂暂停，随后尝试恢复原状态。标准数据包括插件标准数据目录和专属 KV；AstrBot 全局配置、外置数据库等不在备份范围内。插件管家自身的标准数据不可用。插件放在代码目录里的数据仍可能随代码打包。

**导入**：在「导入 / 恢复」上传本功能生成的 ZIP，选择要恢复的代码、配置和数据，可按列全选或点击「全部选择」。确认后，管家先备份本机受影响内容，再执行覆盖。

导入时记住这几点：

- 现有插件默认跳过；未选组件保持原样。
- 普通插件的配置和标准数据**整体替换，不做合并**，空内容也会清空目标。
- 恢复后通过 AstrBot 自动加载插件，并由官方加载流程处理缺失依赖，会执行插件代码。新插件默认启用，已有插件保留原启停状态；加载失败会回滚该插件并停止后续恢复。
- 恢复代码时优先校验并绑定备份中的来源；缺少来源时，按插件名、作者及仓库地址唯一匹配官方市场，匹配不到则校验仓库源。市场离线、匹配歧义或校验失败会记录提示并保留待处理来源，不阻止加载。

普通插件安装 ZIP 不能在这里恢复。插件管家自身不能在线恢复。

## 🕘 任务记录与还原

任务记录和文件持续保留，可在任务右上角「⋯」中选择「删除记录及文件」。删除不会影响已安装插件，但会一并删除该任务的下载文件和恢复资料。

导出文件、任务记录及恢复资料默认保存在 AstrBot 运行目录下的：

```text
data/plugin_data/astrbot_plugin_manager/transfers/jobs/<任务 ID>/
```

使用自定义数据目录时，以实际路径为准。

### 还原到导入前

找到带有恢复资料的导入任务，点击「还原到导入前」，选择要还原的内容并确认。还原会覆盖导入后的修改，移除原本不存在的组件；执行前还会备份当前内容。普通插件还原后仍保持停用，确认无误后再加载启用。

**恢复资料就是覆盖前的本机备份**，用于还原，不能作为迁移包上传。需要还原时请保留原任务；确认不再需要后再删除。

ZIP 导入或还原失败时，会尝试恢复失败项并停止后续操作，之前成功的项会保留。进程中断不会自动续跑，请先核对任务记录和插件状态。页面还原无法完成时，先停止 AstrBot，再依据恢复资料中的 `rollback.json` 手工恢复。

## 💡 使用前留意

- 安装、加载和启用会执行插件代码，请只使用可信来源。
- ZIP 不加密，配置和数据可能含密钥、聊天记录等敏感内容，分享前核对范围。
- 单次 ZIP 最多 **256 MiB**，解压后最多 **1 GiB**，单文件最多 **128 MiB**，文件与目录合计最多 **20,000** 个；JSON 清单最多 **8 MiB**，插件数量最多 **256** 个。

## 🧪 开发验证

在同时包含 `AstrBot` 和 `astrbot_plugin_manager` 的父目录执行：

```powershell
.\AstrBot\.venv\Scripts\python.exe -m pytest astrbot_plugin_manager\tests -q
.\AstrBot\.venv\Scripts\python.exe -m ruff check astrbot_plugin_manager
```

AstrBot 源码不在相邻目录时，通过 `ASTRBOT_SOURCE` 指定路径。
