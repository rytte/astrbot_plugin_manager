# 插件管家 🧩

AstrBot 插件的日常琐事，交给管家。聊天里用 `/pm` 查找、安装、启停，WebUI 里管理来源、分享清单、备份迁移。

## 🌟 功能亮点

- **插件管理**：搜索安装、检查更新、启停重载和确认卸载。
- **命令与工具**：查看插件详情、命令和模型工具，按实际归属展示。
- **来源管理**：关联官方市场与仓库，校验插件身份并切换更新源。
- **清单分享**：导出 JSON 清单，由接收者选择插件与来源安装。
- **备份恢复**：打包代码、配置和标准数据，批量选择恢复范围，支持还原到导入前。
- **在线加载**：点击「待加载」标签，确认后加载并启用，无须重启 AstrBot。

## 📋 命令速查

| 命令 | 管家能做什么 |
| --- | --- |
| `/pm help` | 查看帮助 |
| `/pm list` | 查看插件列表 |
| `/pm refresh-market` | 刷新插件市场 |
| `/pm search <关键词> [--page <页码>]` | 搜索插件市场 |
| `/pm add <仓库地址或市场ID>` | 安装插件 |
| `/pm check-update` | 检查更新 |
| `/pm update <插件名>` | 更新插件 |
| `/pm remove <插件名> [--all]` | 卸载插件 |
| `/pm info <插件名>` | 查看插件信息 |
| `/pm enable <插件名>` | 启用插件 |
| `/pm disable <插件名>` | 停用插件 |
| `/pm reload <插件名>` | 重载插件 |
| `/pm cmds [页码]` | 查看全部命令 |
| `/pm tools [页码]` | 查看模型工具 |

插件名允许省略 `astrbot_plugin_` 前缀。

## 命令说明

### 搜索与安装

```text
/pm search 天气
/pm search 天气 --page 2
/pm refresh-market
/pm add rytte/astrbot_plugin_manager
/pm add https://github.com/rytte/astrbot_plugin_manager
```

* 搜索仅查询官方市场，按名称、作者、简介、标签和市场 ID 匹配，每页 20 项。
* 优先读取 AstrBot 的本地 `plugins.json` 缓存，缓存缺失、不可读或为空时才联网。
* 联网查询与市场刷新 60 秒超时。

安装支持两种输入：

- **市场 ID**：使用完整的 `作者/插件技术名`，不能省略 `astrbot_plugin_` 前缀；含空格时用引号包住整个 ID。找不到时直接报错。
- **仓库地址**：使用 AstrBot 支持的完整 HTTP(S)、SSH 或 SCP 风格 Git 地址。

安装由 AstrBot 处理下载、版本检查、依赖和加载，**会执行插件代码**。

### 查看、启停与重载

`list` 列出全部插件；`cmds` 和 `tools` 每页 20 项，默认第一页。工具列表涵盖插件、AstrBot 内置、MCP、Agent 及子工具，并按实际归属展示。`info` 查看目标插件的基本信息、安装记录、当前更新源、关联来源数量，以及它拥有的指令和工具。

`info`、`update`、`enable`、`disable`、`reload`、`remove` 接受**插件技术名或安装目录名**，中文显示名只用于展示。配置项 `allow_prefix_omission` 默认开启，允许省略 `astrbot_plugin_` 前缀；其余部分须精确匹配，出现歧义时会要求使用完整名称。

`reload` 只重载目标插件。停用插件使用 `enable`；加载失败插件请到官方 WebUI 处理。管家不能停用或卸载自己，AstrBot 保留插件也不能卸载。

### 检查与更新

```text
/pm check-update
/pm update astrbot_plugin_example
```

`check-update` 检查全部插件的已关联来源，汇总当前更新源可更新项、其他来源的新版本和检查失败项。`update` 可直接使用，无须先检查或追加 `confirm`；它只检查目标插件的**当前更新源**，远端版本号更高时才通过 AstrBot 更新，并保留原启停状态和最初安装记录。

没有当前更新源时，请先在插件页面关联来源。管家不会根据元数据仓库地址推断更新源，也不会自动改用其他来源；执行前身份、来源或本机状态变化时会拒绝更新。内置插件、管家自身和加载失败插件请通过官方页面处理。

检查由用户主动触发，没有定时联网任务。最多同时请求 3 个来源，每次请求最长 60 秒。聊天中的进度和结果从原会话返回，与 WebUI 用户的任务记录独立。

### 卸载确认

管理员可在群聊或私聊卸载插件，须在 **60 秒内**以相同参数追加 `confirm`：

```text
/pm remove astrbot_plugin_example
/pm remove astrbot_plugin_example confirm
```

默认保留配置和数据。若要同时删除配置、文件数据和插件专属 KV，两次命令都带上 `--all`：

```text
/pm remove astrbot_plugin_example --all
/pm remove astrbot_plugin_example --all confirm
```

确认须由同一管理员在同一平台、同一会话发出，插件身份、状态和删除范围也须一致。不能跨群或在群聊与私聊之间确认；超时、重载管家或重启 AstrBot 后须重新申请。

## WebUI 页面与来源管理

在 WebUI 打开**插件管家 → 插件页面**。页面包含「导出 / 分享」「导入 / 恢复」「任务记录」三个页签，插件列表支持名称、目录搜索和状态筛选，并显示插件图标；图标缺失时使用默认图标。

磁盘上尚未注册的插件显示「待加载」。点击标签并在弹窗确认后，管家通过 AstrBot 加载并启用该插件，无须重启，会执行插件代码；加载期间标签显示「加载中…」，结果直接在页面提示，不写入「任务记录」。加载失败的插件请到官方 WebUI 处理。

导出时可填写「导出名称」，用于任务名称和下载文件名，系统自动添加扩展名。最多 80 个字符，不接受路径或非法文件名；留空时，清单下载为 `plugins.json`，插件包下载为 `astrbot-package-<任务短 ID>.zip`。ZIP 和 JSON 的插件选择互相独立。

### 关联安装来源

| 信息 | 含义 |
| --- | --- |
| 安装记录 | 管家执行安装时记录的方式与时间；旧插件只有首次观察到的 AstrBot 来源，不能证明最初安装来源 |
| 已关联来源 | 同一插件可以关联多个官方市场 ID 或仓库地址 |
| 当前更新源 | 唯一生效的更新来源，与 AstrBot 原生绑定同步，供官方 WebUI 更新使用 |

缺少记录的插件显示「来源未知」。新增关联或切换更新源不会改写最初安装记录；备份中的安装记录只供参考。

1. 点击插件旁的「来源管理」，填写完整官方市场 ID 或不含凭据的 HTTPS 仓库地址。
2. 点击「校验身份」，核对来源中的插件技术名、作者及已有仓库地址。市场先查本地缓存，必要时联网复核；仓库检查远端元数据。
3. 点击「保存关联」，同时设为当前更新源。切换已有来源时点击「设为更新源」，切换前会重新校验。

校验预览有效期为 10 分钟，插件身份或来源变化后须重检。内置插件、身份不完整或磁盘与运行时身份冲突的插件不能修改来源；已有自定义市场记录可展示，目前不支持新增或切换。

<details>
<summary>作者匹配与插件信息变更</summary>

多人作者使用英文逗号分隔。市场作者可以是本机完整作者集合的子集，例如市场 `Soulter` 可匹配本机 `Soulter,FateTrial`；仓库要求完整作者集合一致。显示名不参与身份判断。

修改作者、显示名或版本后，点击「更新信息」同步管家记录与导出规则。此操作不重载插件、不改源码、不迁移数据，也不改写当前更新源。作者变更后，已有来源须重新校验才能用于分享清单；插件技术名变更仍按身份冲突检查。

若作者已变更且插件仍在运行，附带标准数据前须先停用。备份读取原运行标识下的 KV，恢复时写入包内作者对应的标识。操作期间请避免在其他入口同时修改同一插件或来源。

</details>

### 在页面检查与更新

点击「检查更新」会检查全部已关联来源，不受列表筛选或勾选影响。列表展示当前更新源的结果，各来源的版本和失败原因可在「来源管理」中查看。其他来源有新版本时，先设为当前更新源，再重新检查。

当前更新源的版本号更高时，点击「更新」并确认，由 AstrBot 更新、处理依赖和重新加载，保留原启停状态，结果写入「任务记录」。检查后插件身份、来源或版本变化须重检；插件信息已变更时先点击「更新信息」。仅修改代码而未提高版本号不会提示更新。

## 用 JSON 清单分享插件

JSON 清单用于让对方**从来源重新安装插件**，只包含显示名、市场 ID 和仓库地址，不包含代码、配置、数据，也不锁定版本。

1. 在「导出 / 分享」选择「插件清单 JSON · 分享安装」。为插件关联并校验官方市场或 HTTPS 仓库来源，勾选后点击「导出清单 JSON」。导出使用已有记录，无须联网。
2. 将 JSON 分享给对方。对方在「导入 / 恢复」选择「插件清单 JSON · 选择安装」，上传后等待后台预检。
3. 在预览中选择插件和来源。两种来源同时存在时默认市场；市场不可用时可手动改选仓库，不会自动回退。
4. 核对后启动安装，在「任务记录」查看结果。已有同身份插件会跳过，身份冲突禁止覆盖。

预检完成后 **1 小时内**可安装，勾选和来源自动保存。刷新页面或从任务记录点击「继续选择安装」可接回选择；过期、失败或中断时点击「重新预检」，使用原清单创建新任务，旧记录保留。

正式安装与 `/pm add` 共用 AstrBot 安装流程，会执行插件代码，通常无需重启或手动启用。实际版本以安装时从所选来源获取的内容为准。

<details>
<summary>清单格式与预检规则</summary>

清单格式为 `astrbot-plugin-manager-manifest` v1，示例：

```json
{
  "format": "astrbot-plugin-manager-manifest",
  "schema_version": 1,
  "name": "插件分享",
  "plugins": [
    {
      "display_name": "示例插件",
      "market_plugin_id": "alice/astrbot_plugin_example",
      "repo_url": "https://github.com/alice/astrbot_plugin_example"
    }
  ]
}
```

- `name` 必须是非空合法名称；`market_plugin_id` 和 `repo_url` 至少提供一个，另一个可省略或留空。
- `display_name` 仅供展示，真实名称、作者和版本来自来源元数据。同时填写两种来源时，仓库身份须与市场 ID 一致。
- 拒绝未知字段、未知版本、任意安装包下载地址、重复来源和自定义市场。格式不符时请重新导出。
- 市场安装须取得最新条目，仅有缓存时不可安装；正式执行前版本、仓库、下载地址或本机目标变化会拒绝该项，要求重检。
- 仓库预检下载并解析插件包，正式安装时由 AstrBot 重新获取。仓库默认使用默认分支，GitHub 地址可包含 `/tree/分支`；仅含仓库来源时无需访问市场。

</details>

## 用 ZIP 插件包备份与迁移

ZIP 保存当前实例的插件文件，可按需附带配置和标准数据，适合备份或迁移环境。

### 导出备份

1. 在「导出 / 分享」选择「插件包 ZIP · 备份环境」，勾选插件。表头全选只作用于当前筛选，保留筛选外的选择。
2. 按需勾选「附带当前配置」和「附带标准数据」，也可使用批量附带选项。
3. 点击「导出插件包」，核对范围并确认。含标准数据的已启用插件会在快照时短暂暂停，随后尝试恢复原状态。
4. 在「任务记录」等待完成并下载 ZIP；若恢复启用状态失败，请按任务提示到 WebUI 检查。

页面默认不选插件。常用组合可通过「保存规则」保存，下次点击「应用已保存规则」再调整；保存空选择会清空规则。规则在当前实例内共享，不锁定版本，导出始终使用本次选择，无须先保存规则。

| 组件 | 内容 |
| --- | --- |
| 代码（必带） | 插件安装目录，排除 `.git`、`.venv`、`venv`、`node_modules`、`__pycache__` 和 Python 字节码 |
| 来源信息（默认附带） | 安装记录、关联来源和备份时的更新源，不包含操作历史、凭据或校验认证 |
| 当前配置（可选） | 已落盘的插件配置文件，不补默认值 |
| 标准数据（可选） | 插件标准数据目录与专属 KV；SQLite 使用 Backup API 快照；管家自身范围见下文 |

备份不包含 AstrBot 全局配置、共享目录、其他插件的 KV 或外置数据库，也不会迁移外部资源和绝对路径。**插件自行存放在代码目录中的数据仍可能随代码导出。**

### 导入备份

1. 在「导入 / 恢复」选择「插件包 ZIP · 恢复备份」，上传本功能生成的 ZIP。普通插件安装 ZIP 和恢复资料 ZIP 不接受。
2. 等待隔离解压与预检，此时不执行插件代码。预检 **1 小时内**有效，本机目标变化或刷新页面后须重新上传。
3. 勾选要恢复的代码、配置和标准数据。可通过表头复选框按列全选，也可点击「全部选择」「清空选择」；列表显示包内插件图标。
4. 点击「确认恢复所选内容」。系统先暂停相关插件、强制备份本机受影响内容，再逐插件恢复。
5. **普通插件完成后保持停用。** 可在列表点击「待加载」并确认加载启用，也可重启 AstrBot 扫描后到 WebUI 手动启用；依赖问题按任务提示处理。

现有插件默认跳过，新插件必须包含代码；新插件勾选配置或数据时自动选中代码，取消代码也会取消其配置和数据。缺失或不可恢复的组件不能选择。

未选组件保持原样。普通插件的配置和标准数据**整体替换，不做合并**，空数据也会清空目标数据。身份冲突时拒绝覆盖，不自动改名；AstrBot 保留插件不参与迁移。

<details>
<summary>插件包格式、配置校验与来源恢复</summary>

插件包格式为 `astrbot-plugin-manager` v1，每个插件须包含 `payload/<目录名>/sources.json`。不接受无来源快照的旧 v1 或原 v2，请用当前版本重新导出。

预检检查路径、身份、校验值、版本、依赖和组件声明。配置严格按所选代码的 schema 校验，不做类型转换、补默认值或旧字段兼容。导入不自动安装依赖，依赖声明不接受 URL、extras、pip 参数或外部依赖文件。

覆盖代码时一并恢复来源：安装记录标为备份参考，新关联标为「待校验」，保留备份时更新源的说明，但不自动写入 AstrBot 当前更新源。请在来源管理中「校验并设为更新源」；仅恢复配置或数据时保留本机来源。

可迁移来源限不含凭据的 HTTPS 地址，不支持的地址会省略并提示。普通插件的代码、配置、数据路径取自实际运行实例，标准布局分别为 `data/plugins/<目录名>/`、`data/config/<目录名>_config.json`、`data/plugin_data/<插件名>/`，插件名、目录名与 KV 使用的 `plugin_id` 可能不同。

</details>

### 迁移管家的来源关联与导出规则

导出时选中管家并勾选「附带标准数据」，ZIP 中的 `payload/<管家目录>/manager-data.json` 会包含**全部已安装插件**的来源关联和保存规则，不受其他插件的选择影响。不包含任务、历史、预检、恢复资料、管家 KV 或完整数据目录。

导入时管家**只能恢复标准数据**，不能在线覆盖代码或配置：

- 来源按技术名与完整作者集合匹配，目录可以不同。新关联合并并标为待校验，保留本机已有安装记录、关联状态和当前更新源；未安装或身份不匹配项跳过并提示。
- 导出规则整体替换，空规则清空本机规则；规则无效时在执行前拒绝恢复。
- 普通插件先恢复，管家数据最后恢复。管家保持运行，恢复前仍会备份，并支持从任务记录还原。

## 任务记录与恢复资料

页面任务及文件持久保存，不会自动清理。进度、详情和下载仅任务创建的 WebUI 用户可访问；导入、导出等写任务串行执行，并与聊天管理操作共用锁。

默认存储位置如下（相对于 AstrBot 运行目录）；自定义数据目录时以实际配置为准：

```text
data/plugin_data/astrbot_plugin_manager/
├─ sources.json                 来源记录
└─ transfers/
   ├─ rule.json                 保存的导出规则
   └─ jobs/<任务 ID>/            任务记录、导出文件、预检文件及恢复资料
```

在任务右上角「⋯」菜单选择「删除记录及文件」，会删除该任务目录中的记录和文件，不影响已安装插件。处理中任务不可删除；删除带恢复资料的任务后，将无法再用该资料还原。

### 还原到导入前

**恢复资料是导入覆盖前的本机备份**，包含文件、专属 KV、来源和组件存在标记。它用于撤销本次覆盖，不能作为迁移包上传。

1. 在已结束且有恢复资料的导入任务中点击「还原到导入前」。
2. 等待校验资料和本机身份，选择要还原的代码、配置或标准数据。还原会覆盖导入后的修改，原来不存在的组件会移除。
3. 核对后确认，系统先备份当前所选内容，再执行还原；还原代码时也还原原来源记录。
4. 普通插件完成后保持停用，可点击「待加载」并确认加载启用，或重启 AstrBot 扫描后手动启用。管家仅还原来源关联和导出规则，保持运行。

还原预检 **1 小时内**有效，关闭弹窗或刷新后可从任务记录「继续选择还原」，过期可重新预检。本机文件、KV、来源或启停状态变化须重检；删除原导入任务会使相关还原预检失效。还原会创建新任务并保留还原前的备份，不修改原导入备份。

### 失败与中断

| 操作 | 失败后的处理 |
| --- | --- |
| 聊天管理、页面更新 | 不保证自动回滚，可能已有文件或状态变更；按提示到官方 WebUI 核对 |
| 待加载插件 | 页面提示失败原因，尝试清理本次运行记录并恢复原停用标记；到官方 WebUI 核对 |
| JSON 清单安装 | 记录失败并继续其他项，成功项保留；失败安装可能留下文件或依赖 |
| ZIP 导入、页面还原 | 尝试恢复失败项的覆盖前备份和原启停状态，停止后续项；之前成功项保留 |
| ZIP 导出 | 文件变化或快照失败时终止，未完成任务不生成插件包 |

进程中断不会自动续跑。优先查看任务记录和本机状态；页面还原仅支持当前实例保留的恢复资料，不接受上传恢复资料 ZIP。资料缺失、损坏或不完整时会拒绝执行。

<details>
<summary>页面还原失败时，如何人工处理恢复资料</summary>

先停止 AstrBot，保留任务文件，再根据恢复资料中的 `rollback.json` 逐项处理：

1. 将 `before/<目录名>/` 中的代码、配置、数据恢复到记录的目标位置。按存在标记处理；原来不存在的组件应移除新增内容。
2. `kv.json` 是带类型的插件专属 KV 快照，不能直接覆盖 AstrBot 全局数据库。按记录的 `plugin_id` 恢复对应键值；启停偏好按 `module_path`、`was_enabled`、`was_inactive` 核对，必要时使用维护脚本。
3. 若含 `source_state`，将 `record` 恢复到管家 `sources.json` 的对应目录项，通过 AstrBot 偏好存储恢复 `core` 指定的来源键；`null` 表示原来不存在，只处理记录涉及的键。
4. 管家自身快照位于 `before/<管家目录>/manager-data.json`。按 `sources_exists`、`rule_exists` 恢复 `sources.json` 与 `transfers/rule.json`；原来不存在时移除新增文件，保留任务目录和其他数据。

清单安装中断时，可结合任务 `job.json` 的 `pending_install` 与 WebUI 状态核对当时正在安装的插件，重新预检后再决定安装范围。

## 限制与注意事项

| 项目 | 上限 |
| --- | --- |
| ZIP 压缩包 | 256 MiB |
| ZIP 解压内容 | 1 GiB |
| 单文件 | 128 MiB |
| JSON 清单 | 8 MiB |
| 插件数量 | 256 |
| 文件与目录节点总数 | 20,000 |

这些限制针对单次导入或导出的整体内容，超过任意一项会报错。任务还会估算暂存、备份和替换所需空间，并额外预留 64 MiB；空间不足时在覆盖前失败。

- **ZIP 不加密**，配置、文件和 KV 可能含 Token、Cookie、聊天记录等敏感内容。分享前核对范围，妥善保管备份及恢复资料。
- 校验值和身份校验不能证明代码安全。只导入可信内容，安装或启用前自行审查。
- 拒绝路径穿越、符号链接、硬链接、目录联接、特殊文件、Windows 保留名称和大小写或 Unicode 冲突路径；目录无法完整读取时直接失败。
- 页面接口验证 WebUI JWT，写操作另需用户绑定的短期确认凭据，不接受 API Key 或页面资源 token。
